Implement the approved plan `.claude/plans/$ARGUMENTS.md` (spec: `.claude/specs/$ARGUMENTS.md`).

You are the orchestrator, running on the cheaper model. Keep your own context small: delegate the coding.

0. Run `bash "${CLAUDE_PLUGIN_ROOT}/scripts/plan-check.sh" .claude/plans/$ARGUMENTS.md` from the repository root and keep its full output for step 5. If it exits 2, report its `error=` and `summary=` lines and stop. If it exits 1, show me every `error=` line verbatim and its `summary=`, say that no task will be dispatched, and stop: I fix the plan, or, for a finding I judge a false positive, I add `Override: <code> task <N>: <reason>` (or `Override: <code> plan: <reason>`) to the plan header and run the build again. Never add or edit an `Override:` line yourself, and never edit the plan to make it pass. If it exits 0 and the output has any `blocked=` line, show those lines and stop: I resolve each by rewriting it as `- Task N: RESOLVED: <decision>`. If it exits 0 otherwise, show me each `warning=` and `overridden=` line (or say there are none), then, because this build is my approval, set the plan header's `Approved:` line to `Approved: yes` and its `Status:` line to `Status: IN_PROGRESS`. In worktree mode, make these two edits on the worktree copy of the plan once step 2 has created it (that copy is the one named in `Plan:`), and leave the original plan in the main checkout unchanged. Because the worktree may start from the default branch, whose files can differ, then re-run `plan-check.sh` on that worktree copy before any task's agent is dispatched and handle the result exactly as above (exit 2: report and stop; exit 1: print every `error=` line with the override hint and stop; exit 0: print the `warning=` and `overridden=` lines). In branch mode make the edits now. This step is the gate in hookless mode too: never skip it.
1. Read the plan and the spec. If the spec has an unresolved "Open questions" section (older specs), stop and tell me. `assumed` rows are not blockers, and neither are numbered questions with a `default:` under the spec's table: their defaults stand. Step 0 already refused a missing plan and any `blocking` row.
2. If any task's first line reads `Task status: IN_PROGRESS` or `Task status: DONE`, this is a resume: skip the questions below and continue in the current checkout and branch, but first run `bash "${CLAUDE_PLUGIN_ROOT}/scripts/default-branch.sh"` from the repository root; if it prints `on_default=yes`, do not continue: tell me and ask, since I may switch back to the feature branch. A worktree build resumes from a session started inside its worktree. Otherwise choose where the work happens and which branch it starts from, before any task's agent runs. First name the branch: pick `<type>` from the spec's goal (`fix` if it corrects a bug, `refactor` if it restructures code without changing behaviour, `chore` if it is maintenance that changes no product behaviour such as dependencies, build, CI, tooling, docs or a version bump, otherwise `feature`), then run `bash "${CLAUDE_PLUGIN_ROOT}/scripts/branch-name.sh" <type> <slug>` from the repository root. Its `branch=` value is `<branch>` below; it already includes the project prefix from `.claude/branch-prefix` when the repo has one. If it exits 1, report its `error=` and `summary=` lines and stop.
   - Run `bash "${CLAUDE_PLUGIN_ROOT}/scripts/default-branch.sh"` from the repository root. Offer the base choice only if it exits 0, prints `on_default=no`, and `git status --porcelain -- . ':!.claude/plans' ':!.claude/specs' ':!.claude/worktrees'` is empty. Otherwise start from the current branch: if the script exited 1, give its `summary=` line; if the tree has uncommitted changes, say in one line that starting from the default branch is not offered because switching base could mix or lose those changes.
   - Offer **Worktree** only if `git rev-parse --git-dir` and `git rev-parse --git-common-dir`, both run from the repository root (`git rev-parse --show-toplevel`), print the same path and `EnterWorktree` is among your tools. Otherwise use **Branch** and say why in one line (this session is already in a linked worktree, or `EnterWorktree` is unavailable).
   - Ask me once, with one `AskUserQuestion` call holding the questions that apply: header `Git workflow`, question "Where should this build happen?", options **Branch (default)**: "Work in this checkout. <branch> is created unless you are on a non-default branch and start from it, in which case the work stays on that branch." and **Worktree**: "Create a separate checkout in .claude/worktrees/<slug> on <branch>; this checkout stays untouched."; and header `Start from`, question "Which branch should the work start from?", options **Current branch (default)**: "Start from <current branch, or HEAD if detached> as it is now." and **Default branch**: "Start from <default= value>, the repository's default branch." Leave out any question my approval to build already answers, and do not call `AskUserQuestion` if none is left. If `AskUserQuestion` is unavailable, use the defaults. Any answer that is not a clear choice of **Worktree** means **Branch**, and any answer that is not a clear choice of **Default branch** means **Current branch**.
   - **Branch**: if the tree has unrelated uncommitted changes, stop and ask (`.claude/plans`, `.claude/specs` and `.claude/worktrees` do not count). Never work on the default branch. With **Current branch**: if `default-branch.sh` exited 1 (no default branch found), you are on the default branch, or you are on a detached HEAD, run `git switch -c <branch>`; on any other branch, stay on it. With **Default branch**: run `git switch --no-track -c <branch> <ref>`, where `<ref>` is the script's `ref=` value.
   - **Worktree**: run `bash "${CLAUDE_PLUGIN_ROOT}/scripts/worktree.sh" <slug> <branch> <start>` from the repository root, where `<start>` is `HEAD` for **Current branch** or the `ref=` value for **Default branch**. If it exits 1, report its `error=` and `summary=` lines and stop; for `error=copy-failed` the worktree and branch already exist, so also tell me the cleanup commands in its `summary=` and do not run them yourself. Otherwise call `EnterWorktree` with its `path=` value. From then on all commands, every task's agent, `security-reviewer` and the reviewer work in that worktree, and its `.claude/specs/` and `.claude/plans/` hold copies of the spec and plan. If it printed `ignored=no`, tell me to add `.claude/worktrees/` to `.gitignore`. If it printed `dirty=yes`, tell me that uncommitted changes in the original checkout are not in the worktree. Do not use any other worktree procedure or skill.
3. Each task goes to the agent its title tag names (its title is the text after `### Task N: `, which its `open=` line repeats): no tag -> `implementer`; `[backend]` -> `backend-implementer`; `[frontend]` -> `frontend-implementer`; `[qa]` -> `qa-engineer`; `[devops]` -> `devops-engineer`; `[docs]` -> `docs-writer`. Plan-check already refuses an unknown tag, a tagged `Manual:` task and a `[qa]` task before an implementation task (`task-tag`), so `open=` order runs every `[qa]` task after the implementation tasks. Below, "the task's agent" means that agent; every rule for the `implementer` applies to it unchanged. Dispatch tasks one at a time, never in parallel, because each task's agent writes the plan. The order is that of the `open=` lines in the latest plan-check output, lowest first; never dispatch a task at `Task status: DONE` (review-fix dispatches in step 6 excepted); a task at `Task status: IN_PROGRESS` was interrupted and is dispatched again in `open=` order, and its agent resumes from the work already written. Invoke the task's agent with only that task, the spec sections it references, and the spec's "Assumptions and open questions" section. Set the Agent tool's `model` parameter to the task's `Model:` value and its `effort` parameter to the task's `Effort:` value; this step is the explicit instruction to set them. Omit `model` when the task has no `Model:` line and `effort` when it has no `Effort:` line, so the `implementer` (frontmatter `model: inherit`) runs on this session's current model and effort, and a tag-routed builder runs on its frontmatter model. If the Agent tool has no `effort` parameter (Claude Code before 2.1.292), omit it and say so once. Before each dispatch, run `cp <plan> <plan>.before`, using the `Plan:` path. In worktree mode, also give each task's agent the worktree path and tell it that every path in its task means the same repo-relative path inside that worktree. Start every prompt to the task's agent with the line `Plan: <path>` and, on the second line, `Task: <N>`, where `<path>` is `.claude/plans/<slug>.md` in branch mode and the absolute path of the plan copy inside the worktree in worktree mode; where hooks run, the dev-flow implementer gate denies a call without it. If the gate denies a call to the task's agent, stop and show me its message verbatim; do not retry with another agent or work around it. A task whose title starts with `Manual:` needs me: do not dispatch it; show me its `Change:` and `Done when:`, set its first line to `Task status: IN_PROGRESS`, and wait for my reply; only if I report it done, set it to `Task status: DONE` yourself, append my report as one `- Task N: <text>` line under `## Deviations` and continue with the next `open=` task; if I say it cannot be done, leave it at `Task status: IN_PROGRESS`, append `- Task N: BLOCKED: <text>` and stop.
4. The task's agent, not you, sets its task's `Task status:` (`IN_PROGRESS` when it starts, `DONE` when every verify passes), extends its Files block and appends its Deviations lines. Never set the Task status or write Deviations for a dispatched task. After each reply from the task's agent:
   1. Run `bash "${CLAUDE_PLUGIN_ROOT}/scripts/plan-edit-check.sh" <plan>.before <plan> <N>`. On exit 1 or 2, show its `error=` and `summary=` lines and stop.
   2. Re-run plan-check on the plan.
   3. If the reply reports every verify passing, confirm that no `open=N:` line remains. Otherwise stop and report that the task's agent did not set Task N to `Task status: DONE`.
   4. If the reply is `BLOCKED`, or does not report every verify passing, and plan-check prints no `blocked=N ` line, append `- Task N: BLOCKED: <the reason in one line>` under `## Deviations`. Then stop and report. Do not re-dispatch, do not set a Task status, and do not edit the plan to get past a gate. Do not improvise design changes.
5. When all tasks are done, collect the review inputs for `security-reviewer` and `reviewer`:
   - `base=$(git merge-base HEAD "$(git symbolic-ref --short refs/remotes/origin/HEAD 2>/dev/null || echo main)")`
   - the diff: `git diff "$base"` (committed and uncommitted work), plus each new file from `git ls-files --others --exclude-standard -- . ':!.claude/plans' ':!.claude/specs' ':!.claude/worktrees'` shown with `git diff --no-index /dev/null <file>`. New files under `.claude/plans/` and `.claude/specs/` are left out of that list, so if the plan's deliverable lives there, pass those files to the reviewer explicitly. If the result is too large to paste, pass `git diff --stat "$base"` and the list of changed and new files instead, and say the reviewer must Read them.
   - the log: `git log --oneline "$base"..HEAD`
   - the output and exit code of a fresh `bash .claude/test-cmd` run, or "no .claude/test-cmd" if it does not exist
   - the output of `bash "${CLAUDE_PLUGIN_ROOT}/scripts/plan-check.sh" .claude/plans/$ARGUMENTS.md`, re-run just before invoking the reviewer (not only step 0's, so an override I added mid-build is shown), including every `overridden=` and `warning=` line, and the plan's `## Deviations` section (or "no deviations")
   - the output and exit code of `bash "${CLAUDE_PLUGIN_ROOT}/scripts/plan-scope.sh" <plan> "$base"`, re-run before each review
   - the spec and plan paths (in worktree mode, the copies inside the worktree).
   Neither reviewer has a shell, so paste these inputs into each prompt. Invoke the `security-reviewer` subagent with those inputs and no `model` or `effort` parameter (its frontmatter pins Opus), and keep its findings and verdict for step 6.
6. Invoke the `reviewer` subagent with the same inputs as `security-reviewer`, with the Agent tool's `model` and `effort` set from the plan header's `Review: <model> <effort>` line, or neither when the plan has none, so it runs on this session's current model and effort. If either review returns no verdict (neither `APPROVE`, `APPROVE WITH MINOR` nor `CHANGES REQUIRED`, for example because it stopped on missing inputs), stop: do not go on to step 7, but delete `<plan>.before` and give step 7's finish report without running `verify-done` (what was built, files changed, evidence of verification, the dispatches, remaining findings including that this review did not run, the branch name and in worktree mode the worktree path, and no merge or push), and leave the `Status:` line unchanged. If either review returns `CHANGES REQUIRED`, send the blocker and major findings from both reviews back as new dispatches to the agent of the task whose Files block lists the finding's path, with `Task: <N>` set to that task; when several Files blocks list it, use the highest-numbered such task; when no Files block lists the path, send them to `implementer` with `Task: <highest-numbered task>`. Set the plan's `Status:` line to `Status: DONE` only if it prints no `open=` and no `blocked=` line and `verify-done` found no failure (in worktree mode, on the worktree copy; the original in the main checkout stays unchanged); otherwise leave `IN_PROGRESS` and list those lines and failures. Delete `<plan>.before`. Finish with: what was built, files changed, evidence of verification, the agent dispatched for each task, the model and effort passed to each of those dispatches and to the `reviewer` (`session` where none was passed), the `security-reviewer` verdict and remaining findings, remaining `reviewer` findings, scope drift (every `drift=` path and the reviewer's scope-drift findings), every plan-check override and deviation (from the step-5 plan-check output), and anything not verified. Do not merge or push.
